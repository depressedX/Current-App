# MVP 推荐方案：听感与场景

状态：DCLAP 音频向量与固定概念匹配已接入；当前查询随机选择一个真实概念向量，明确标注模拟意图，不理解输入文本。下面的个性化排序与反馈学习仍为后续方案。实现见 [听感分析](11-semantic-analysis.md)。

## 核心选择

采用 **场景理解 + 内容与听感匹配 + 个人偏好排序**。

不把需求限制在「阴郁／明亮、舒缓／激烈」两个轴。支持风格、声音质感、氛围、节奏、人声与歌词等组合表达，例如「浪漫、朦胧、有律动，但别太吵」。

初期不训练推荐模型，不接 Contextual Bandit；候选先来自用户选定歌单。音频分析与文本匹配使用现成模型，再用反馈校准。

## 三类数据分开

| 数据 | 内容 | 更新方式 |
|---|---|---|
| 歌曲特征 | BPM、风格分数、音色、氛围、音频向量 | 分析、外部数据、人工修正 |
| 当前意图 | 场景、想要的听感、排除项、明确限制 | 自然语言、本次调整 |
| 个人偏好 | 长期喜好、某场景下的喜好、临时疲劳 | 用户反馈 |

爱心只影响 Current，永不同步网易云收藏。反馈不修改全局歌曲属性，临时需求不覆盖长期口味。

## 1. 初始特征覆盖什么

采用 **少量可解释属性 + 音频 embedding（向量）**。不要求把每种听感都提前录成固定标签。

| 特征组 | 需要覆盖的表达 | 初期做法 |
|---|---|---|
| 节奏 | BPM、律动、节拍稳定性 | BPM 与可信度；律动用模型分数或语义匹配 |
| 情绪 | 阴郁、明亮、平静、亢奋 | Valence、Arousal 与多标签情绪分数 |
| 风格 | Rock、House、R&B，以及混合风格 | Top-K 分数，不强制单一分类 |
| 声音质感 | 柔和、尖锐、温暖、厚重、轻盈 | 优先用音频语义匹配，验证后再增加独立属性 |
| 氛围与空间 | 朦胧、空灵、亲密、浪漫、宽阔 | 音频语义匹配；保留用户对词义的个人校准 |
| 人声与编制 | 纯音乐、柔和人声、钢琴、吉他 | 人声分数、乐器标签或语义匹配 |
| 动态 | 少突发变化、避免突然爆发 | 音频分段分析与动态统计；未分析时记未知 |
| 歌词 | 浪漫、悲伤、叙事；是否打扰注意力 | 可用歌词时独立分析，不用歌词情绪替代声音听感 |

注意：

- BPM 不等于激烈程度；低响度不等于轻柔。
- 浪漫不等于慢歌，朦胧不等于悲伤；音频与歌词可以表达不同情绪。
- 每项保留来源、分析片段、模型版本；有可信度则保存，没有则记未知。
- 语义相似度是排序信号，不当成标签概率或客观结论。
- 新维度必须能改善真实场景结果；重复或不稳定的维度不直接叠加。

## 2. 理解场景，不给场景套死规则

解析结果包含：场景、听感描述、明确条件、排除项、不确定项。保留原文，避免解析丢失「浪漫朦胧」等细节。

| 输入 | 初始理解与排序方向 | 不能擅自推断 |
|---|---|---|
| 下班路上听 | 已知通勤场景，优先用该场景历史偏好；没有历史则提供多样候选，允许补充「放松／提神」 | 下班一定想安静；路程一定多长 |
| 开车时候听，快乐一点 | 明亮、轻快、有律动；匹配驾驶场景历史 | 必须高 BPM、高音量或强烈刺激 |
| 睡前听，轻柔一点 | 柔和、低激烈程度；优先少突发变化、人声不突出 | 必须纯音乐；未知动态也算平稳 |
| ML 时候听，浪漫朦胧一点 | 亲密、温暖、空间感、柔和人声或器乐、连贯律动；歌词另看 | 必须慢歌、某一种风格，或永久写入个人画像 |

这些方向是可修正的初始假设。界面最多展示少量可调整条件，例如「轻柔」「朦胧」「少人声」，不要求用户填写特征表。

不确定但不影响起播时，先播放再校准；关键含义冲突、候选不足时再询问。不悄悄忽略明确限制。

## 3. 生成与调整队列

流程：

1. 从选定歌单取可播放候选，读取已有分析结果。
2. 明确硬条件先筛选，例如 BPM 区间；未知项不冒充满足。
3. 用原始听感描述匹配音频向量，同时比较可解释属性。
4. 加入个人场景偏好、长期偏好，扣除重复与疲劳惩罚。
5. 组成有变化但听感连贯的队列，保留少量符合条件的探索歌曲。
6. 收到反馈后，只重排尚未播放部分。

概念评分：

> 听感语义匹配 + 明确属性匹配 + 场景偏好 + 长期偏好 − 重复与疲劳

明确条件优先。相关信号如「低 Arousal」「柔和」「低能量」控制重复计权，不能靠同义项数量压过其他要求。权重通过小规模听测调整。

## 4. 反馈如何生效

| 反馈 | 推荐接入后的处理 | 范围 |
|---|---|---|
| 喜欢 | 提高歌曲偏好；相似歌曲小幅加分，保留当时场景 | 当前场景与个人长期偏好，分别保存 |
| 不适合此刻 | 本轮排除歌曲，记录与本次需求不匹配，不猜原因 | 当前会话 |
| 暂时不想听 | 冷却期减少这首歌，惩罚随时间消退 | 有时效的歌曲偏好 |
| 不喜欢这首 | 长期降低该歌曲排序，不直接否定整个风格 | 个人歌曲偏好 |
| 下一首 | 切歌，不自动解释为负反馈 | 当前队列 |
| 撤销 | 删除对应反馈；若已影响后续排序则重新计算 | 对应事件 |
| 输入「再朦胧一点」「人声少一点」 | 修改指定听感，保留其他条件 | 当前会话 |

现有 UI 的三种负反馈范围只说明作用范围，不能识别到底是风格、歌词还是氛围不对。定向校准优先允许修改原需求；可选的维度反馈后续再加，不强迫每次回答原因。

反馈绑定操作时的歌曲、账号和场景，不错记到下一首；修改范围更新同一事件，重复点击不无限增权。

## 5. 开源组件选择

| 组件 | 用途 | 采用方式 |
|---|---|---|
| [AudioMuse-AI](https://github.com/NeptuneHub/AudioMuse-AI) | 音乐库分析、文本搜索、相似歌曲和歌单流程 | 完整参考应用，不等同于直接嵌入的 SDK |
| [Essentia](https://essentia.upf.edu/models.html) | 基础测量与风格、人声、情绪等预训练分析 | 按需选模型，建立明确属性 |
| [LAION CLAP](https://github.com/LAION-AI/CLAP) | 文本与音频向量匹配 | 优先验证「浪漫、朦胧、温暖」等开放听感 |
| [AudioMuse-AI-DCLAP](https://github.com/NeptuneHub/AudioMuse-AI-DCLAP) | 轻量音频向量提取 | 原模型验证后再比较速度与效果 |
| [Music2Emo](https://github.com/AMAAI-Lab/Music2Emotion) | 情绪标签、Valence、Arousal | 情绪匹配不足时再评估加入 |
| [librosa](https://github.com/librosa/librosa) | 基础音频与动态分析 | 实验、分段统计与质量检查 |

先做离线分析实验，App 消费特征与排序结果；不预设所有模型能直接跑在 iPhone 上。中文听感检索需比较原文与翻译／改写后的效果，不能默认英文模型理解准确。

前提：拿到可解码且可用于分析的音频。歌曲 ID、登录成功或能播放，不等于已具备分析输入；短片段结果不冒充整首特征。

许可分别检查代码、依赖与权重：AudioMuse／DCLAP 仓库为 AGPL-3.0；[Essentia](https://essentia.upf.edu/licensing_information.html) 库与模型许可不同，MTG 模型通常包含非商业限制。选型不等于已完成商用许可确认。

## 6. 实施与验证

1. 选 50–100 首熟悉的歌，覆盖上述四个场景和多种风格；确定分析输入来源。
2. 提取基础属性与一种音频向量，先不叠加多个情绪模型。
3. 四个场景分别比较「仅情绪双轴」与「属性 + 听感语义」的结果。
4. 用户盲听候选，记录契合程度、具体偏差；改写同义需求检查稳定性。
5. 加入场景反馈，检查喜欢、不合适、冷却和长期不喜欢是否按各自范围生效。
6. 有明确短板再增加特征或模型；有足够交互后再评估 Contextual Bandit。

验收重点：

- 快乐的驾驶歌曲不只剩高 BPM；轻柔的睡前歌曲能减少突发爆发。
- 浪漫朦胧能跨风格找到契合歌曲，而非退化为「慢、悲伤」。
- 「再朦胧一点」保留原有场景与其他要求；未知特征不编造解释。
- 不同用户的「下班」允许逐渐形成不同偏好。
- 临时场景反馈不污染长期口味；下一首不产生负向风格标签。
- 爱心不压过明确条件，也不触发网易云收藏请求。

记录原始需求、解析与版本、候选及评分项、反馈范围、时间、账号、分析来源；不保存 cookie。私密场景原文默认只保留在本机，不写日志、不默认上传或跨会话复用；可清除历史与反馈。

判断标准：用户是否更快找到此刻想听的音乐，不以播放时长越长越好。

BPM 条件后续读取 `PoolSong.resolvedBPM`：网易云百科优先、本地估计兜底；来源分开保留，未知项不冒充满足。见 [来源验证](10-bpm-sources.md)。
