# BPM 来源与网易云百科验证

日期：2026-10-20。

## 已验证

使用 Current 的加密请求实现和临时匿名会话，直接请求网易云，不通过第三方代理、不读取保存的账号凭据。

- 接口：`/api/song/play/about/block/page`，参数 `songId`；Current 使用 eapi 加密路径。
- 返回：`data.blocks[].creatives[]`，定位 `creativeType == "bpm"` 或标题为 BPM 的条目，读取 `uiElement.textLinks[].text`。
- 实测《降温》167727 返回 **63**，与用户提供截图一致；《幻听》167655 返回 58；347230 返回 76。
- 生产入口 `NetEaseAPI.songBPM(id:)` 再次实测《降温》返回 63，非仅文档或 mock 证明。

协议入口参考：[API Enhanced song_wiki_summary](https://github.com/NeteaseCloudMusicApiEnhanced/api-enhanced/blob/main/module/song_wiki_summary.js)。上述请求结果只证明这次样本可用，不保证所有歌曲都有 BPM，也不保证未来不需要登录。

## 采用规则

1. 真实歌曲先获取网易云百科 BPM，请求超时 8 秒；原创演示音频跳过。
2. 只接受明确 BPM 条目中的单个有限数值，范围 20–400；不从年份、歌曲 ID、自由文本或范围字符串猜数值。
3. 有网易云值则优先采用，不做半速／倍速折算。
4. 缺失、接口错误、网络失败时，回退本地音频估计；不因百科失败让整首分析失败。
5. 两者均不可用时保留未知，不虚构结果。

`PoolSong.resolvedBPM` 是后续筛选入口；`bpmSource` 标明网易云百科／本地估计。`wikiBPM` 保存获取时间和来源版本，`AcousticFeatures.bpm` 始终只表示本地测量，不被官方值覆盖。

基础音频分析仍用于其他维度，因此新任务拿到官方 BPM 后仍分析电平等数据。若音频获取失败，已拿到的百科 BPM 会保留，其他分析任务状态仍如实报告失败。

## 旧数据与 UI

- 旧档案缺少新增字段时仍能读取。
- 仅保留歌曲详情页的单曲获取 BPM；不提供全局批量补全入口。
- 已有声学结果时只请求百科，复用原始结果，不下载或重新解码音频。
- 列表和详情显示解析后的 BPM 与来源，同时保留本地估计供对照。
- 获取过程为独立状态「获取网易云 BPM」，仍支持串行、暂停、取消和账号隔离。
- 诊断日志新增 songWiki 操作与结果数量，不记录原始百科内容或歌曲身份。

## 对照 Kumone：当前算法并不等同

本地阅读 `Core/Player/Analysis/TrackAnalyzer.swift`：Kumone 从 STFT／log-mel 的频谱变化提取起音，去均值后做自相关，加入速度先验并细化峰值，还做后续节拍跟踪。

Current 当前独立实现只对短时 RMS 能量包络求差和自相关，没有复现 Kumone 的频谱起音链路，真实音乐适用性更弱。前期的“参考”是方向与分层参考，不应理解为算法移植或效果相当。

“周期强度”只是自相关强度。Current 还检查峰值相对背景的突出程度，0.65 不表示 65% 的 BPM 置信度；曲目起音不明显或峰形不突出时可能判未知。

此次按用户要求改来源优先级，没有假称已升级为 Kumone 算法。后续本地算法改进需要独立实现频谱起音与真实歌曲对照；不能只放宽门槛让未知消失。

## 验证

- `zsh Scripts/check-core.sh --live-bpm`：结构化解析、无效／缺失值拒绝、真实匿名百科请求。
- `zsh Scripts/check-analysis.sh --download`：官方优先、本地估计保留、缺失／断网回退、旧档案读取、旧未知结果无音频下载补全，以及既有分析链路。
- Current 与 CarPlay SDK 编译检查；不下载模拟器。


## 重新分析

歌曲池 → 已分析 → 歌曲详情 →「重新分析」。完成或失败的任务均可重跑。

- 强制重新获取百科 BPM、音频并计算，不复用旧声学结果。
- 重跑中保留并标记上次结果，整条分析成功后替换；失败保留旧 BPM、维度和完成时间。
- 暂停／重启保留完整重跑标记；失败后重试仍跑完整链路，不会误走只补全 metadata 的快捷路径。
- 同一任务未完成时不重复入队。
- 只缺 BPM 时优先「获取网易云 BPM」；若百科没有、本地也无法可靠估计，重跑后仍可能未知。
