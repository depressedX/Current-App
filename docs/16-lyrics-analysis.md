# 歌词索引与主题检索

## 产品入口

- 我的 → 歌曲池 → 补全歌词索引：旧歌曲单独补歌词，不重下音频。
- 单首详情 → 歌词 · BGE → 更新歌词索引：重新获取歌词、生成新记录，失败保留旧结果。
- 歌曲池 → 歌词检索：输入中文主题，查看候选歌曲、命中段落、原词／译词、时间与相似度；可沿用播放器播放。
- 新歌曲分析自动尝试歌词索引。音频权限失败不阻止已成功的歌词索引；补歌词也不会把音频失败改成成功。

不根据歌词缺失判断纯音乐；无中文原词或网易云中文译词时标为暂不支持，不做自动翻译。歌词缺失、索引失败和模型版本过期分别显示。

## 模型与数据

使用已验证的 BGE-small-zh-v1.5 社区 INT8 ONNX，约 24 MB，随 App 打包，复用 ONNX Runtime 1.24.2，无额外下载步骤。原作者 MIT 声明、许可证、转换来源、版本和哈希随资源保存。

`Semantics/Lyrics/` 必须同时包含图文件、外部权重和 tokenizer；不能只复制约 168 kB 的 ONNX 图。

| 数据 | 存放位置 | 来源／空间 |
|---|---|---|
| 歌词索引状态、版本、时间、来源摘要 | 歌曲池 catalog 的 lyrics 字段 | BGE 歌词空间 |
| 歌词段落、时间与 512 维向量 | Application Support/Current/LyricsAnalysis/UUID.json | 账号与歌曲双重校验 |
| 网易云百科 | wikiMetadata | 网易云百科，独立保留 |
| 音频、乐器与风格结果 | features / semantic / genres | 各音频模型，独立保留 |

歌词文件使用与现有分析存储相同的原子写入和文件保护。记录不可变；新结果保存成功后再更新 catalog 引用。废弃文件在 catalog 持久化后延迟回收，不立即删除可能仍被引用的记录。

## 分析链路

1. 通过现有登录会话请求 `/song/lyric`，读取 lrc 与 tlyric。
2. 去时间戳、演奏／制作人员信息、无歌词占位文本，保留每行时间。
3. 中文来源筛选与电脑实验一致；原词、译词分开处理。每块 4 行、步长 2，同来源重复块去重。
4. 使用已固定 tokenizer 的大小写敏感 BERT 规则和 WordPiece；每块最多 256 token，CLS pooling 后 L2 归一化。
5. CPU 单线程，每次一块。歌词索引复用歌曲池的串行、暂停、播放抢占、后台与低电量／温度限制。
6. 查询使用同模型和官方中文检索指令，只编码输入主题；歌词不包含歌名、歌手或音频特征。
7. 扫描当前账号的有效歌词记录，按最高相关段落聚合到歌曲，返回前 10 个候选。

检索前先取消并等待分析任务退出，避免两份推理会话重叠；查询结束后按原暂停状态继续。切换账号、取消或移除歌曲后，旧查询结果不能跨账号返回。

模型不做歌词情绪分类；分数不是置信概率，也不与 DCLAP 向量直接比较。播放仍可能受账号与版权权限限制。

## 验证与边界

- 原生 tokenizer 与 Hugging Face 对照：中文、拉丁字母、重音、特殊 token、控制字符、emoji、超长截断。
- 对齐 ORT 1.24.2 后，10 条合成文本的原生／Python 向量余弦最低约 0.99999996。
- 生产 Swift 重跑已验证歌单：8 首、164 个窗口；“分别、离别”前两名仍为送别和おつかれSUMMER。原电脑实验的运行时版本和 batch 不同，不要求所有分数逐位一致。
- 回归：缺词／不支持语言、持久化、损坏索引、取消、账号隔离、失败保留、单独补索引、音频不可用仍可检索。
- 已做 iPhone / CarPlay SDK 构建。未下载模拟器；iPhone 12 的延迟、内存与温升仍需真机验收。

测试：`zsh Scripts/check-core.sh`、`zsh Scripts/check-analysis.sh`、`zsh Scripts/check-lyrics.sh`。

PC 只生成合成一致性基准；实际歌词索引在 iPhone 本地生成。复现方式见 [PCLyricsReference](../Tools/PCLyricsReference/README.md)。
