# 歌曲池与分析链路

> 客观特征新版见 [客观歌曲分析 v1](12-objective-song-profile.md)。DCLAP 相似度仍是实验结果，不作为确定分类。
状态：基础链路与 DCLAP 听感链路已接入。详情见 [听感分析](11-semantic-analysis.md)。最低设计基线 iPhone 12／A14，iOS 17+。

## 动线

「我的 → 歌曲池 → + → 选择歌单 → 全部加入／单曲 +」。加入后默认暂停，由用户开始。

歌曲池包含「待处理」「已分析」两组。详情展示基础维度、分析音频范围、计算耗时与引擎版本。失败可重试，歌曲可移出。

不在此刻页、音乐库选歌或 CarPlay 插入任务管理；加入歌曲池不改变播放队列，不生成歌单，也不修改网易云收藏。

## 状态与控制

| 状态 | 行为 |
|---|---|
| 等待分析 | 已保存歌曲 metadata，尚未启动 |
| 获取音频 | 获取当前可用地址，限量下载临时文件 |
| 分析听感中 | 基础测量后，逐窗计算 DCLAP |
| 分析完成 | 保存基础值、听感向量与版本，删除临时音频 |
| 分析失败 | 保存可读原因，等待手动重试，不无限重试 |

- 同一时刻最多一个任务；暂停取消当前任务，等待它退出后才启动下一个。
- 暂停保留已完成结果；续跑从当前歌曲重新开始，不声称支持网络字节断点续传。
- 未完成任务重启后恢复等待状态，默认暂停。
- 后台、播放或加载音乐、低电量模式、严重／临界热状态会让分析暂停。条件解除后，仅在用户没有主动暂停时恢复。
- 账号切换取消旧任务并拦截迟到结果；不同账号池子隔离。演示曲库使用独立 demo 空间。
- 歌曲按账号＋来源歌曲 ID 去重，多个歌单可关联同一项。
- 整单导入使用完整 trackIds，分批请求详情；不可读取项需提示，不能静默把前 60 首当成整张歌单。

## 当前真正分析什么

原生 AVAssetReader → 11.025 kHz 单声道 Float PCM → 约 10 ms 帧统计 → 起音能量自相关与汇总。

| 结果 | 含义与限制 |
|---|---|
| BPM 估计 | 45–200 范围，弱周期记未知；有半速／倍速风险 |
| 节奏周期强度 | 自相关峰强度，不是校准置信度 |
| 平均／峰值电平 | dBFS，不是 LUFS，也不代表主观激烈程度 |
| 电平变化 P90–P10 | 片段帧级电平分布，不是全曲动态范围认证 |
| 过零率 | 基础时域描述，不直接推断明亮或柔和 |
| 范围／版本／耗时 | 显示测量来自哪一段及哪版引擎 |

最多取中间 45 秒；不足则分析现有时长，少于 8 秒或接近静音失败。单片段可能遗漏前奏／副歌变化，不用于断言整首无突发变化。

听感阶段使用 DCLAP 的 512 维音频向量与 PC 预计算概念匹配；详情显示相似度、窗口及版本。旧基础结果需要补全听感分析。

## 听感阶段

已接入 DCLAP：独立的 48 kHz 前处理、512 维音频向量、PC 预计算概念、版本校验和按账号保存。旧基础结果不自动视为听感就绪，需点“补全听感分析”。

详细前处理、存储、模拟查询与操作见 [听感分析](11-semantic-analysis.md) 和 [PC 预计算](../Tools/PCPrecompute/README.md)。窗口均值用于当前匹配，不宣称整曲稳定；播放和后台策略沿用上述控制。

## iPhone 12 性能约束

| 项目 | 当前措施／后续门槛 |
|---|---|
| 解码 | 最多 45 秒，流式消费 sample buffer，不保留整首 PCM |
| 临时音频 | 每次一个文件；按实际容器保存后缀；下载上限 40 MB，下载结束再次核验；资源超时 90 秒；重启清理遗留临时音频 |
| 计算 | detached utility task；UI 和播放不做 DSP |
| 暂停 | 每个解码 buffer 检查取消；旧任务完全退出前不启动下一首 |
| 存储 | actor 编码与原子写入，版本号阻止旧快照覆盖新结果 |
| 播放 | 不创建分析 AVPlayer、不改音频会话；播放／加载时取消分析 |
| 后台 | 不靠音频后台权限维持分析；回前台再继续 |
| 模型 | 一次一个窗口；模型驻留、转换精度、CPU/GPU/ANE 分配需实测 |

45 秒、11.025 kHz Float 单声道约 1.9 MiB；实现连这段 PCM 也不整体保留。帧级包络约 36 KiB。此为算法数据量，不是 App 总内存保证；解码器、网络与 UI 仍有额外占用。

### 真机放行标准（待测，不是已达到）

- iPhone 12 冷启动和连续 100 首，无 OOM、无持续内存爬升。
- 分析页滚动与按钮响应无持续卡顿；暂停后不再开始新首。
- 播放开始即让路，前后台切换、断网、过热均正确恢复或提示。
- Instruments 记录 CPU、峰值 physical footprint、主线程长任务和 Energy Log；基础链路目标增量内存低于 50 MiB，完整 App 无系统内存告警。
- 引入语义模型前单独测峰值内存（目标增量低于 150 MiB）、每首耗时、温升、电量、精度与模型加载成本；不达标则继续优化或采用用户明确选择的外部分析方案。

主机测试不能替代真机结果。当前不承诺已消除所有 iPhone 性能问题。

## 数据与推荐边界

保存歌曲信息、状态、基础结果、范围、版本和来源歌单，不保存签名音频 URL、cookie 或临时音频。未完成／失败结果不参与推荐；基础结果不能满足听感条件。

现有随机推荐暂不读取歌曲池。后续接入只消费满足本次查询所需维度的结果，避免把管理操作与日常听歌混合。

## 验证入口

- `zsh Scripts/check-analysis.sh`：真实 AVFoundation 解码、合成节奏、持久化、单任务、暂停继续、播放／后台让路、账号切换、移除。
- `zsh Scripts/check-core.sh`：已有登录、协议、播放地址与队列检查。
- 手动：演示空间 → 我的 → 歌曲池 → 加入原创曲库 → 继续分析 → 切换已分析 → 查看详情；暂停、重启、切账号和播放歌曲后再次检查。

压缩格式与下载回归：`zsh Scripts/check-analysis.sh --download`，只连接临时 loopback HTTP 服务，不访问用户账号。
