# 听感分析：当前工程方案

> 客观特征新版见 [客观歌曲分析 v1](12-objective-song-profile.md)。DCLAP 相似度仍是实验结果，不作为确定分类。
## 分工

| 位置 | 工作 | 随 App 分发 |
|---|---|---|
| `Tools/PCPrecompute` | 配套 CLAP 文本编码器预计算固定概念 | 否 |
| `Resources/Semantics/concept-vectors.json` | 16 个听感概念的 512 维向量 | 是 |
| `Resources/Semantics/Models` | DCLAP 音频 ONNX 图 + 外部权重 | 是，合计 22,411,906 字节 |
| `DCLAPFrontend` | Swift / Accelerate 音频前处理 | 是 |
| `DCLAPEngine` | 官方 ONNX Runtime 1.24.2 原生绑定 | 是 |
| `OpenRouterIntentResolver` | 解析 BPM 条件、听感概念和权重 | 是，个人 Key；默认 `openrouter/free` |
| `MockListeningIntentResolver` | 随机选择概念向量 | 仅保留离线测试入口，生产生成不调用 |

不做模型下载管理页。音频模型随 App 更新，文本模型只留在电脑。运行库也有体积，不能把 22.4 MB 说成 App 最终增量。当前没有 Core ML 转换；后续可以替换推理适配层，不改歌曲池和向量空间协议。

## 音频链路

下载一个临时音频 → 基础声学分析 → DCLAP → 原子保存 → 删除临时音频。

- 基础测量仍是 11.025 kHz 流式读取；网易云百科 BPM 优先，本地 BPM 后备。
- 听感使用 AVAudioFile 按源 PCM 帧定位，AVAudioConverter 显式流式转换为 48 kHz mono Float32；10 秒窗、5 秒 hop。
- 最多取前／中／后三个 20 秒区域，共最多 9 窗。重复起点去重；不足 10 秒不伪造向量。
- 每窗先 int16 量化，STFT 2048 / 480、周期 Hann、reflect center、128 Slaney mel、0–14 kHz、power dB，无 top_db 截断。
- 窗口输出均值后 L2 归一化。保存窗口起点与计算耗时，不宣称覆盖整首。
- 余弦相似度排序，显示前 6 个概念；不是概率，也没有统一“合格”阈值。

## 存储

参考 Kumone `AnalysisStore`：分析结果属于 Application Support，独立于音频缓存，用 actor 串行管理。

```text
Application Support/Current/
  song-pool.json             # 任务、基础值、听感摘要及记录 ID
  SongAnalysis/<UUID>.json   # 不可变 512 维音频向量、账号、歌曲 ID、空间版本
```

- 任务摘要不塞全部向量，阶段更新不反复重写向量。
- 原子写入、设备首次解锁后可读。读取校验账号、歌曲 ID、schema、空间版本、维度及有限值。
- 重新分析先写新记录，成功后换引用。失败保留旧值；未完成／版本不兼容的结果不参与推荐。
- 历史 JSON 缺少 `semantic` 仍可读取；点“补全听感分析”升级。
- 移除或替换后无引用的记录留一天，再于成功保存歌曲池后清理，避免误删待提交记录。
- 不保存分析音频，不记录 cookie、签名 URL 或歌曲原始文本到诊断日志。

## 查询链路（临时）

文本输入 → `OpenRouterIntentResolver` → **JSON Schema 推荐查询** → 校验范围／概念／条件强度 → 曲风与 BPM 筛选 → 音频向量听感门槛 → 合格候选加权排序 → 一次加入全部匹配歌曲。

- 每项听感条件增加 `requirement`：普通要求为 `required`，曲风命中集合与 BPM、逐项听感条件取交集；明确说“最好／优先”才是 `preferred`，仅参与排序。`weight` 只控制合格候选排序，不能降低筛选门槛。
- House、摇滚要求按 Discogs 曲风证据筛选。House 包含模型支持的 14 种 House 风格，摇滚按 Rock 家族匹配；其他必需听感按完整音频向量计算余弦相似度，不能使用前六名标签代替。
- 门槛：对应风格最高分 ≥ 0.2，且 ≥ 全部候选最高分的 75%；不累加多个相关标签。它是保守筛选规则，不代表校准概率，仍可能误判或漏选。
- 正向曲风要求排除缺失、旧版本和低证据结果；负向曲风要求排除证据达到门槛的歌曲。音频、百科原始标签分别保存，不建立统一曲风体系。百科只读取 songTag/曲风字段，不能混入推荐标签、语种等字段；其准确性未验证。
- 必需正向听感相似度 ≥ 0.25，必需负向听感相似度 < 0.25。0.25 是基于当前池分数分布选定的初始保守门槛，未经人工标注集校准；不是情绪概率，后续需分概念校准。只有可选项的查询保持加减权排序。
- “120 BPM 左右”默认转为必需的 110–130 BPM（含边界），仍按接近 120 程度排序；“最好 120 BPM 左右”仅优先该区间。未知 BPM 不满足必需范围。明确范围按原值，不再额外扩展。
- “伤感的 120 BPM 左右的 House”要求 （音频 House 证据 OR 模型选中的百科 House 原始标签）AND 110–130 BPM AND 伤感相似度 ≥ 0.25；任一项失败都排除，其他项高分不能补偿。
- 一次返回全部合格歌曲，无匹配则提示，不自动放宽任何必需条件；听完后手动从头再听，不追加重复副本。
- 明确曲风或已识别听感词被模型遗漏时拒绝生成；没有可选措辞却返回可选条件也拒绝。无法表达的细分曲风由模型标记为不支持，不降成宽泛听感。
- 新会话本地保存完整歌单和解析条件；旧分批历史重播时展开已保存的全部候选，不重新筛选，需重新生成才能使用新规则。诊断日志仍不保存原始需求或模型正文。
- 歌单持续展示解析条件及实际 BPM 范围。旧本地条件缺少 `requirement` 时按旧可选偏好读取；网络响应必须包含该字段。

网络层使用 `MacPaw/OpenAI 0.5.3`，请求 `/api/v1/chat/completions`，启用严格 `json_schema` 和 `provider.require_parameters`。模型返回概念 ID 和权重，App 查本地同空间概念向量，不接受模型生成的 embedding。Key 在「我的 → AI 设置」保存／清除／测试连接，仅存独立 Keychain 项；只发送本次需求、听感词表和两份注明来源的可用曲风词表，不发送音频、完整歌单或网易云凭据。模型拒绝、输出截断、非法条件、免费额度不足和网络失败会明确提示，不回退随机选歌。

反馈仍只属于 Current；没有同步网易云收藏，也还没有训练个性化权重。

## 手机约束

每首使用一个后台 utility worker、一个 ONNX session、单线程 CPU 推理。每次只保留 10 秒 PCM 和一窗 mel；不缓存整曲。每首结束释放 session，不永久驻留模型。

播放／加载、后台、低电量、过热时取消；解码和前处理检查取消，单次 ORT run 完成后检查取消。旧任务退出才开下一首，暂停响应上限取决于一个推理窗，必须真机实测。

iPhone 12 性能仍需真机 Instruments 验收：峰值 footprint、暂停延迟、连续任务温升和播放响应。Mac 对照只能证明实现一致，不能代替真机数据。

### 分来源曲风

- 音乐库独立显示音频风格和百科曲风，保留各自名称；只选一份就只查那份，两份都选时取并集，再与其他筛选条件取交集。
- OpenRouter 接收当前账号已完成歌曲中可用的音频大类／细分曲风与百科原始曲风词表，返回来源明确的 ID。来源 ID 必须属于本次词表；不发送逐歌记录、歌曲名称、账号或凭据。
- 必需正向曲风项取并集，负向曲风项排除其并集；必需 BPM 和每项听感仍取交集。来源标签没有听感向量，不能拿百科标签替代伤感等听感门槛。
- 百科文字没有模型置信分，不与音频分数相加，也不改写音频分析结果。来源命中只用于条件和单独的排序加分。新词表能表达的其他风格也可用于查询；没有对应标签时不擅自扩成流行／电子。
