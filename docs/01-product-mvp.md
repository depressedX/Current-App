# 产品 MVP

## 目标

用一句话开始听歌，在听歌中表达感受。先验证交互，不训练模型。

## 核心路径

1. 连接网易云，或进入明确标注的演示空间。
2. 选择一个用户歌单作为选歌范围。
3. 输入「阴郁的摇滚，别太激烈」。
4. 生成队列并开始播放。当前是随机选取，文本只作为本次意图记录。
5. 喜欢、跳过，或说明哪里不合适。
6. 在「我的」重播最近队列，查看和清除本机反馈。

采用队列而非单首生成：能一次看到结果，减少等待，也能在 CarPlay 连续听。

## 反馈语义

| 动作 | 本次行为 | 后续设计方向 |
|---|---|---|
| 很合此刻 | 记录，继续播放 | 场景内正向信号 |
| 下一首 | 切歌，不记负向标签 | 弱信号，可能只是临时跳过 |
| 这次不想听 | 记录并切歌 | 当前会话降权 |
| 情绪不太对 | 记录并切歌 | 调整场景情绪要求 |
| 风格不太对 | 记录并切歌 | 修正风格匹配 |
| 听腻了 | 记录并切歌 | 有时效的疲劳惩罚 |

爱心和负向反馈永不同步网易云收藏，只服务 Current 推荐权重。当前尚无推荐算法，记录不会影响随机排序。
播放器用并列的「不合适」「喜欢」大按钮承载核心反馈；下一首仍不等同负向反馈。

## 不在本期

BPM 筛选、音乐风格/情绪识别、自然语言模型、Contextual Bandit、下载管理、替代音源、歌词、社交、Mac/iPad。

## 视觉与交互

随系统切换浅深色，暖红色强调，系统字体和紧凑列表。首页输入是起点，常驻迷你播放器；完整播放页不放技术参数。
视觉 token 和组件规则见 [设计规范](05-design-system.md)。
不让用户先做批量打标；数据生产以后嵌入听歌过程。
CarPlay 用系统模板，驾驶中仅选队列、控制播放和轻量反馈。
